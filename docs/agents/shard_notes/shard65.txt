
nov03-w2 (sub_080634D8, ~45 min, no match):
  The pointer setups after the first sub_08006EE0 call are a gcse/PRE artifact: with plain scalar
  locals `s16 x, y; u16 w, h;` (address-taken in the loop only, no pointer vars) the compiler itself
  hoists &x/&y/&w/&h to the end of the first block and emits the `xp = x0` copies before the loop
  (ROM's `adds r7,r5; adds r5,r6`). But then the sub_08008CC4(10,&w,&h,..) args reuse the hoisted
  regs (ROM rematerializes `add r1,sp,#0x48`) -> 474 bytes, frame 0x5c.
  Init inline must be the `resource &= 0xFFFF; ...(resource|0x60000) ...(resource|0x80000)` variant
  (ROM keeps resource in r4 for both orrs), with obj=&draw in sl, table in r9.
  Best size-wise: explicit wp/hp/x0/y0 assigned right after the first call, loop using x0/y0 directly,
  manual init with obj/index/size locals: 472 bytes, 129 diff lines (sound+packed spill OK, but
  regs: obj r9/table r5 vs ROM sl/r9, and no x0->xp copies). Adding explicit `xp=x0; yp=y0` spills x0/y0.
  Permuter (--allow-control-diff, 5 min) produced nothing useful.
