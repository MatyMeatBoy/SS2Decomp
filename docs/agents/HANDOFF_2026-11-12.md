## Lessons worth carrying to the next game

1. The hardest functions were held back by decompiler artefacts, not by missing
   register tricks: shared `goto` tails, pointer temporaries, `s32` for 16-bit
   values, wrongly merged or split variables. Normalise those first.
2. Measure with register-normalised diffs and fix in address order; most raw
   differences are reload rotation caused by one earlier site.
3. The compiler source and its RTL dumps answer "why this register" in minutes.
   The mechanisms that mattered are tabulated in the playbook.
4. Any mechanical idea should be a script guarded by the build ("keep only if
   the object is identical" or "keep only if the count does not get worse").
   That is what lets small models and background jobs do real work safely.
5. Keep `make compare`, `make nonmatching` and `check_tree.py` as the gate for
   every commit, and write the mechanism into the shard notes, not only the
   result.

## Environment notes

- Windows shells need `export PATH="/c/msys64/ucrt64/bin:/c/msys64/usr/bin:$PATH"`,
  including for `git commit` (the pre-commit hook runs Python and make).
- A fresh checkout needs the git-ignored `tools/agbcc*` directories (including
  `agbcc_sdk_cc` and the other `agbcc_sdk_*`) copied from a working one.
- Never run two builds in one checkout. Background searches belong in a second
  checkout; stop them by PID, not by image name.
- `unwrap_func.py` writes CRLF on Windows; normalise the module to LF.

## Porting

A PC or other-platform port does not need matching assembly for the 26
routines. Replace them by role:

- BIOS stubs (`Div`, `Sqrt`, `ArcTan2`, `CpuSet`, `CpuFastSet`, `LZ77UnComp*`,
  `ObjAffineSet`, `RegisterRamReset`, `SoftReset`, `VBlankIntrWait`): small C
  implementations with the documented GBA semantics.
- `crt0` and the interrupt dispatcher: platform start-up and a frame callback.
- The scheduler in `sched` (task switch by saved register context): rewrite as
  C coroutines or threads; this is the one piece that needs design, because
  every `Task...` function yields through it.
- `SoundMainRAM` / `MPlayMain`: use a C mixer for the m4a engine; the matched C
  parts of `m4a_1_*.c` already describe the player state.

Hardware register and VRAM accesses in the game C are the larger porting job;
the data pipeline's typed assets are its other prerequisite.
