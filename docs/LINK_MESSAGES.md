Reviewed source revision: `47dde703fb3749813bd4cdb783c8fc5b2b5d9d6b`. This table records matched C in
`sub_0806690C(peer)` and the matched producer wrappers. Dispatch is exactly
`switch (tag - 0x81)`: the raw case index is included to prevent shifted labels.
Source observation is distinguished from a semantic interpretation. No runtime
multiplayer trace was collected for this catalogue. Canonical ROM symbols remain unchanged.

The queue has 50 entries of 0x88 bytes at `gUnk_03006300`, count `gUnk_03006338`.
Entry `+0` is the tag, `+1` the count of 8-byte chunks, `+4` the pending state1,
and `+8` the payload. Chunk counts below are the producer's transmitted length;
padding bytes are not necessarily initialized by that producer. Payload offsets
below start at entry `+8`, not at the transport block. All structure/payload
offsets and address fragments are hexadecimal; byte counts and state values
are decimal unless prefixed with `0x`.

`Player[peer]` starts at `0x03003CE0 + peer*0x14C`; `scene` means the object
pointed to by `gUnk_03005CF4`; active entities are five 0x2E0-byte records through
`gUnk_030056F4`, with ID at `+2`. Remote only means the receiver ignores its own
sender ID. Host means own player ID 0, as tested by these handlers.

`sub_08066898` monitors the outgoing queue and starts broadcast task
`sub_08066720` with 0x800 bytes of allocation. It does not create receive tasks.
`sub_08067AFC` starts the queue monitor and calls `sub_08067A68` for each connected
peer; the latter starts receiver `sub_0806690C` with 0xC00 bytes. The receiver
assembles 8-byte chunks into a 256-byte local buffer and dispatches after the
acknowledgement/barrier sequence. See [LINK_CABLE.md](LINK_CABLE.md) for transport.

## Interpretation limits and corrections

The old table shifted multiple effects from 0x97 onward. In particular, 0x98 is
the 32-byte field-item replication response,0x99/0x9A/0x9B are the pickup
request/response/removal sequence, 0x9C applies a consumable to an actor, and0x9E
starts the sender's display action through65918. 0xA3 and 0xA4 schedule callback tasks with one explicit callback argument; 0xA4 also supplies a guard-bit index;0xA5 invokes793BC,0xA6 writes Player+11E,0xA7 performs the addressed
restore/score sequence, 0xAA calls79CC4 and0xAB carries the five-chunk configuration
block. 0xAC/0xAD/0xAE are three distinct byte stores.

A source identifier or comment alone is not semantic proof:0x91 contains a
packed 8-byte actor record, not an established pure velocity pair;0x95/0x97 read
a selector from the sender's receive block byte 4 low 6 bits, not an established equipped
item record. The producer names callback and pointer do not establish executable
function pointers in 0x84/0xA9. Callback-pointer roles for 0xA3/0xA4 are established separately by the matched task starters. Several byte fields, mode-specific operations
and effect keys remain unresolved. A matched function establishes byte agreement
with the ROM; these notes do not establish an online transport replacement or
runtime behavior under malformed packets.

## Player state and scheduling

The complete 24-byte application block includes continuous player state in bytes
0..7 as well as this mailbox. See [player packet evidence](LINK_PLAYER_PACKET.md).
The first word has an original-ASM-backed packed position layout; word1 has
state-dependent fields and is not specified completely here.

`sub_080003F0` waits for scheduler signal1. The engine conditionally waits for
VBlank before waking that signal; a yield count does not specify elapsed frames.
The announce-ack loop has no local0x3C bound. Sender chunk retries use a counter
of unsuccessful acknowledgement iterations. Receiver phase B increments its
counter only on successful-receive iterations; phase C increments only when the
chunk index repeats with a successful-receive flag, and resets on a new index.
The checks use `> 0x3C`. Completion writes `2 * chunkCount + 1` into the chunk-number
byte before `sub_0800224C` waits for the captured connected/receive-success masks.
These are source-level protocol observations, separate from runtime timing.
